## 2. 从原始题到训练材料：五步

```bash
cd backend

# 1) 归一化 + 按命例切分（避免同一张盘同时进 train/test）
python -m scripts.prepare_bench --ratio 0.75
# → cases.jsonl(160) / train.jsonl(121) / test.jsonl(39) / dataset_card.md

# 2) 评测：每题先算盘 + 检索知识，再让模型答
python -m scripts.bench_eval --dataset mingli_bench \
    --file data/bench/MingLi-Bench/test.jsonl --limit 39 \
    --model minimax-m3.1-flash --tag mingli-test-r1
# → docs/模型评测-MingLi-Bench.md + data/bench/attempts.jsonl（追加）

# 3) 复盘：同一道题错了几次、为什么错、题库缺多少答案
python -m scripts.bench_stats --min-wrong 1
# → docs/题库复盘.md

# 4) 蒸馏：按“累计答错次数”选样本，只写 skills/_draft/（不会自动生效）
python -m scripts.distill_skills --attempts data/bench/train_attempts.jsonl --min-samples 2

# 5) 一轮完整循环（train 挖错 → test 测 → 无卡消融 → 记录 delta）
python -m scripts.distill_round --round 2 --model minimax-m3.1-flash
```

评估与蒸馏的分工：

- `bench_eval` 只负责“跑一遍并记录”；`--no-skills` 是同批题的无技能基线；
- `distill_round` 负责“串起来 + 写 `docs/蒸馏记录.md`”：train 只用来挖错题，test 只在轮末测量一次；
- 技能文件放在 `backend/skills/`，每次 AI 调用前必读，转正流程见 `backend/skills/README.md`。

四步之间的关系：

```
原始题  ──prepare_bench──▶  归一化题 + train/test
                                   │
                          bench_eval（算盘 + 检索知识 + 模型作答）
                                   │
                          attempts.jsonl（每次作答追加）
                             │            │
                    bench_stats       distill_skills
                     （错/答）          （技能卡草稿）
```

## 3. 首轮跑出来的结果（2026-10-25）

| 轮次 | 模型 | 题数 | 准确率 | 未作答/截断 | P50 |
|---|---|---|---|---|---|
| `mingli-test-r1` | `minimax-m3.1-flash`，`--max-tokens 800` | 39（留出集） | **30.8%** | 6 | 8.0s |
| `mingli-test-r2` | 同上，`--max-tokens 1600` | 39 | **38.5%** | 2 | 8.9s |

随机猜的基线是 25%。两轮差距几乎全部来自「输出被截断」——把预算从 800 提到 1600，
准确率就从 30.8% 升到 38.5%，说明**先得把格式问题修掉，再谈推理能力**。

复盘（`docs/题库复盘.md`，78 次作答累计）：

- 39 题里 33 道至少错过一次，其中 21 道两轮都错 → 这些才是稳定的错误模式；
- 6 道题第一轮因截断没作答，第二轮修好 → 属于「格式失败」，不是「判断错误」；
- 错得最多的是「哪一年结婚 / 哪一年发生何事」这类**具体年份定位题**，与「必须先把大运流年
  摊开再逐项对」的判断一致，所以 `_draft/bazi.wrong_answer.md` 第一版写的就是审题顺序。

蒸馏产物（`app/domains/skills/distilled/_draft/`，**未生效**，需人工复核后转正）：

| 文件 | 覆盖 | 状态 |
|---|---|---|
| `bazi.wrong_answer.md` | 31 道错题 / 错 49 次，总结「年份—限定词—选项差异」审题顺序 | draft |
| `bazi.output_truncated.md` | 2 道截断题，总结「先给结论再解释」 | draft |

> 注意：这两张卡是**模型写的草稿**，里面没有具体断语，也没有编造规则；但仍然是 draft。
> 是否转正、要不要合并成一张，需要人看过再决定——这是刻意保留的人工闸门。

## 4. 关键设计（不这样做数据就废）

### 4.1 必须先把盘算好再让模型答

MingLi-Bench 问的是「此命 1996 年发生何事」。模型如果只拿到出生时间，它得先自己排盘；
排错一步整题就废，测出来是「会不会算」而不是「会不会推」。

所以 `scripts/bench/charts.py` 在每题作答前：

1. 用本仓库引擎算出 `chart_facts`；
2. 压成一段盘面摘要（四柱 / 日主 / 十神 / 五行 / 大运 / 流年）；
3. 放进 prompt，并写明「由确定性引擎算出，可直接引用，不要自行重算」。

排盘失败会记 `chart_error`，单独计数，不混进「答错」。

### 4.2 按命例切分，不按题切

同一个命例有 5 道题。按题目随机切，训练集里的盘会出现在测试集里，
模型只要记住「这张盘 2002 年结婚」，测试准确率就虚高。
`prepare_bench` 先按 `case_id` 分组再切，`--seed` 固定，可复现。

### 4.3 错的次数，比错的条数重要

`bench_stats` 输出「错/答」，例如 `3/5`：

- 错 1 次可能只是模型抖动，不值得写卡；
- 错 3 次说明存在稳定的错误模式，才值得蒸馏。

所以 `distill_skills` 默认按**累计答错次数**而不是记录条数取样（`--min-wrong`）。

### 4.4 未作答要单独算

`got` 为空 = 模型没给出可解析答案。它和「答错」是两类问题：

| 现象 | 说明 | 该修什么 |
|---|---|---|
| `answer_not_parsed` | 输出格式跑偏 / 被截断 | 提示词、`--max-tokens`、换输出更短的模型 |
| `选错` | 格式对、判断错 | 补知识、写技能卡、改推理顺序 |

### 4.5 模型要可替换

`--model` 覆盖 `LLM_MODEL`，评测与产品配置解耦。实测同一批题：

| 模型 | 表现 |
|---|---|
| `deepseek-v4.1-flash` | 会先写长推理，容易撞 `max_tokens`（1200/4000 都可能截断），单题 20–30s |
| `minimax-m3.1-flash` | 输出固定 14 字符 JSON，4–16s，适合批量跑 |
| `glm-5.3-flash` | 快（3–7s），偶发输出非 JSON |

> 评测默认用配置里的模型；批量跑建议显式 `--model` 选输出短的，避免把“格式失败”算成“智力不行”。

## 5. 数据卡与已知偏差

`prepare_bench` 会生成 `data/bench/MingLi-Bench/dataset_card.md`，包含类目分布与假设统计。

已知偏差（写进报告，不藏着）：

1. **时区是近似的**：原数据只有「出生地点：usa」这类文字。适配器按国家映射（`usa→America/New_York` 等），
   并在 `chart_notes` 记 `tz_assumed`；边界时辰可能因此偏一柱。
2. **类目极不均衡**：婚姻 44 题、事业 25 题，健康 17、灾劫 2、官非 1，分科准确率波动很大。
3. **题目本身是“断事”**：哪年结婚、发生何事。本项目对用户**不做这类断言**，
   这些题只用于内部评测与蒸馏，不进入产品话术（红线见 `docs/口径说明.md`）。
4. **样本只有 160 题**：单轮准确率的置信区间很宽（±7% 左右），必须多轮累计看趋势。

## 6. 接入其它数据集

`scripts/bench/datasets.py` 已支持四种字段布局：`generic / mingli_bench / fate_bench / baziqa`。

通用格式（每行一个 JSON）：

```json
{"id":"x-001","domain":"bazi","question":"...","options":["A...","B..."],
 "answer":"B","chart_input":{"birth_datetime":"1990-05-20T12:00:00","timezone":"Asia/Shanghai","gender":"male"}}
```

- 有 `chart_input` → 评测时先算盘再答；
- 没有 → 只按题干作答（适合纯知识题）；
- 读不到答案/选项 → **跳过并计数**，不猜。

新增一个来源只需要在 `datasets.py` 加一个字段映射函数，其余四步不变。

---

## 7. 明确不做

- **不做权重微调（SFT/LoRA）**：本仓库的“训练”指「评测 → 错例 → 技能卡 → 注入」这条蒸馏链，
  不训练模型参数。技能卡是纯文本资产，可审计、可回滚，也能被 `git diff` 看见。
- **不把数据集提交进仓库**：许可证与体积都不允许，见第 1 节。
- **不用断事结论做产品输出**：这些题只用于内部评估。
