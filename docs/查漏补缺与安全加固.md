## 4. 关键决策

### D1 密码为什么**不**改成 `sha + md5`

你建议「sha + md5 校验」。这条建议的合理内核是「**不要让明文密码直接进数据库**」，这一点现有实现已经做得更彻底：

- 现状是 **Argon2id**（2015 年密码哈希竞赛冠军，OWASP 现行首选），每次哈希带随机盐，内存硬化（64 MiB）使 GPU/ASIC 暴力破解成本比 MD5 高 6～8 个数量级。
- `md5(sha(pwd))` 或 `sha(md5(pwd))` 属于**快速哈希**，单卡每秒可算上百亿次，且不带盐时彩虹表直接反查。它比 Argon2id 弱，不是「更安全的加密」，只是「更快的摘要」。
- 前端再做一层 MD5 也不会提升安全性：攻击者拿到的是「MD5 值等价于密码」的新口令，服务端仍必须用慢哈希存储它；同时前端哈希无法加盐（盐要从服务端拿），反而引入「哈希即密码」的重放问题。

因此本轮**保持 Argon2id**，并补上两件事：

1. **自动升级**：登录成功时若 `needs_rehash()` 为真，用当前参数重新哈希写回（老数据、调参后都能平滑升级）。
2. **强度校验前移**：注册/重置统一走同一套 `validate_password_strength()`（长度 ≥8、含字母与数字、拒绝常见弱口令、拒绝与邮箱同串）。

> 如果你确实需要「客户端不传明文」的合规诉求，正确做法是 **TLS + SRP/OPAQUE 之类的 PAKE**，或前端用 `argon2-browser` 做预哈希并让服务端再哈希一次；这不是本轮范围，已写入 P2。

### D2 JWT 加固清单

| 攻击面 | 现状 | 本轮处理 |
|---|---|---|
| `alg=none` / 算法混淆 | 已用 `algorithms=["HS256"]` 白名单 | 保持，并加测试锁死 |
| access/refresh 混用 | 已校验 `typ` | 保持，并加测试 |
| 跨系统 token 复用 | **无 `iss`/`aud`** | 新增 `iss=玄枢 / aud=xuanshu-api`，校验强制开启 |
| 令牌被撤销后仍可用 | 靠 `token_version` | 保持；access 校验 `ver` |
| refresh 被窃取后长期可用 | **无服务端记录** | 新增 `refresh_tokens` 表：登录/刷新各发一枚，**用过即废**；检测到重放则整族作废并强制重新登录 |
| 时钟偏移误判 | 无 leeway | `leeway=5s` |
| 暴力破解 | 仅 IP 限流 | 加**按账号失败计数 + 指数退避锁定**（内存态，文档标注多 worker 限制） |
| Cookie CSRF | `SameSite=Lax` + `path=/api/v1/auth` | 保持；refresh 只接受 Cookie，不接受请求体 token |
| XSS 偷 token | access 在 `sessionStorage` | 已是较短 TTL + 每标签页隔离；文档标注残余风险 |

### D3 忘记密码流程

```
POST /auth/password/forgot {email}
  → 无论邮箱是否存在，都返回 200 + 统一文案（防账号枚举）
  → 存在：生成 32 字节随机 token，DB 只存 sha256(token)，TTL 30 分钟，单用户同时只保留最近 3 枚
  → 投递：MAIL_MODE=console 写 var/mail_outbox.log；MAIL_MODE=smtp 走 SMTP
  → 开发环境额外返回 debug_reset_url（生产永不返回，代码里显式判断 APP_ENV）

POST /auth/password/reset {token, password}
  → 查 sha256 命中且未过期未使用
  → 校验新密码强度、不得与旧密码相同
  → 更新 password_hash、used_at，token_version + 1（所有设备下线）
  → 同一用户其余未使用 token 一并作废
  → 写审计日志 auth.password_reset
```

限流：`forgot` 按 IP 3 次/10 分钟 + 按邮箱 3 次/小时；`reset` 按 IP 10 次/10 分钟。

## 5. 接口与数据表变更

### 新增接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/auth/password/forgot` | 免登录 | 申请重置，恒返回统一文案 |
| POST | `/auth/password/reset` | 免登录 | 用一次性令牌设置新密码 |
| GET | `/billing/config` | 免登录 | 支付配置（不含任何密钥） |
| GET | `/auth/sessions` | 需登录 | 当前 refresh 会话数（用于「已登录设备」提示） |
| DELETE | `/auth/sessions` | 需登录 | 注销全部会话（= 登出所有设备） |

### 数据表

- 新增 `password_reset_tokens`：`id / user_id / token_hash / expires_at / used_at / requested_ip / created_at`，唯一索引 `token_hash`，普通索引 `(user_id, created_at)`。
- 新增 `refresh_tokens`：`id / jti / user_id / family_id / expires_at / revoked_at / used_at / user_agent / created_at`，唯一索引 `jti`，普通索引 `(user_id)`、`(family_id)`。
- 两张表都由 `alembic` 新迁移创建，不改已有列。

## 8. 实现记录（写完文档后的实际情况）

### 8.1 真实模型：已接通并达到门槛

`.env` 指向本地 OpenAI 兼容网关（`http://127.0.0.1:7863/v1`），模型 `deepseek-v4.1-flash`，`LLM_JSON_MODE=json_object`（实测该模型接受 `response_format`）。

`python -m scripts.eval_reports --cases 10` 实测：**schema 通过率 100%、引用合法率 100%、降级率 0%、P50 19.0s、P95 24.5s**（详细逐例见 `docs/模型评测.md`，该文件由脚本覆盖生成）。

排查过程中发现三个已在代码里修掉的问题：

1. **`.env.example` 会覆盖 `.env`**：`Settings` 原来把两个文件都放进 `env_file`，而 pydantic-settings 后者优先，导致真实配置被模板里的 `replace_with_*` 盖掉。现在只读 `.env`，模板不参与加载。
2. **技能包的 `max_output_tokens` 太小**：2600/3000 的上限让长命例直接被截断（`finish_reason=length`）。已提到 4000，并在截断重试时改为「压到 900 字以内」的专门提示。
3. **模型自造输出结构**：会多写 `skill/scope/chart_basis`，把 `observations` 写成 `facts: [str]`，或引用未触发的 `rule_id`。处理分两层：
   - 提示词：新增 `system_v2`（篇幅控制 + 字段级要求 + 逐字契约），并把「本次真实触发的 rule_id 白名单」写进用户消息末尾；
   - 代码：`reporting/coerce.py` 做可枚举的整形——丢自造键、折叠 `facts`、摊平对象数组、**删掉自造的 citation/rule**（删了就在 `uncertainties` 里报告条数），但**绝不补内容**：空对象仍然判不合格。
