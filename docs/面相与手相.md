# 面相与手相

本页说明这两个功能的实现边界、合规要求与操作流程。

> 它们**不是排盘引擎**：没有确定性算法，是「图片 + 提示词 → 视觉模型」。
> 因此不进 `registry`，走独立的 `/vision/*` 路由。

---

## 1. 为什么单独成链路

| 维度 | 排盘引擎 | 面相 / 手相 |
| --- | --- | --- |
| 输入 | 结构化参数 | 图片（二进制） |
| 输出 | 可复算的事实 | 模型每次不同的观察 |
| 鉴权 | 免登录可用 | 必须登录 |
| 计费 | 按报告次数 | 按次预扣，模型不可用全额退回 |
| 存储 | 一行 `chart_records` | 文件系统 + `chart_media` 元信息 |

把图片塞进 `/charts/{domain}/calculate` 会让匿名请求刷爆视觉模型账单，
也会让「同一输入同一输出」的引擎契约失效。

---

## 2. 图片处理

| 环节 | 做法 | 原因 |
| --- | --- | --- |
| MIME | 白名单 `image/jpeg` / `image/png` / `image/webp` | 不靠扩展名判断；gif 可能是动图，人脸分析无意义 |
| 大小 | ≤ 5 MiB（`MEDIA_MAX_BYTES`） | 超限直接拒绝，不缩图 |
| 尺寸 | 单边 ≤ 4096 | 同上 |
| EXIF | **上传即重编码剥离** | 人脸照片的 GPS、设备型号、拍摄时间不该留存 |
| 存储 | 按内容寻址：`sha256[:2]/sha256.ext` | 同一张图重复上传不占第二份空间 |
| 路径 | `resolve()` 拒绝 `..` 与绝对路径 | 防目录穿越 |
| 留存 | `MEDIA_RETENTION_DAYS`（默认 30 天） | 到期由 `purge_expired_media` 删除 |

> 剥 EXIF 依赖 Pillow。**缺库时直接报错**而不是退回原图 —— 原图可能带 GPS，
> 「装作用不了」比「悄悄保留元数据」更安全。

## 3. 提示词的三条硬约束

每一份提示词都写入这三条（见 `app/domains/vision/prompts.py`）：

1. **只描述确实可见的形态**。看不清、被遮挡、光线不足的部分写进 `uncertainties`，
   不用「通常」「一般来说」补全。
2. **不做推断性结论**：不推断性格、智力、健康、寿命、命运、财富、婚姻、事业成败，
   不评价外貌美丑。
3. **传统说法必须隔离**：放 `traditional_interpretations`，并逐条标注
   「属传统说法，无实证依据」。

面相另加一条：**不得输出任何可用于身份识别的描述**（姓名、年龄数字、种族、身份、职业）。

## 4. 分析类型

| 面相 | 手相 |
| --- | --- |
| `full` 综合观察 | `full` 综合观察 |
| `forehead` 上庭（额） | `lines` 掌纹主线 |
| `eyes` 眼区 | `mounts` 掌丘 |
| `nose` 鼻区 | `shape` 掌型与指型 |
| `mouth` 口区 | |
| `cheek` 颧颊区 | |

手相另需 `hand_type`（`left` / `right`）。

---

## 5. 额度与失败处理

```
校验图片 → 落盘 → 建 chart_records → 预扣额度 → 调视觉模型
   ├─ 成功：结算，返回结构化观察
   └─ 失败：全额退回，返回 degraded=true + 原因
```

**未配置视觉模型时返回 503 `VISION_NOT_CONFIGURED`**，不回落文本模型。
配置项：

```env
LLM_VISION_BASE_URL=
LLM_VISION_API_KEY=
LLM_VISION_MODEL=
LLM_VISION_TIMEOUT_SECONDS=120
LLM_VISION_MAX_OUTPUT_TOKENS=4000
```

三项（BASE_URL / API_KEY / MODEL）都填齐才算配置完成。

## 6. 数据分层

`chart_facts` **只放用户输入与媒体元信息**：

```json
{
  "media": {"kind": "face", "sha256": "...", "mime": "image/jpeg", "width": 800, "height": 1000, "size_bytes": 123456},
  "analysis_type": "full",
  "question": "..."
}
```

模型输出**不进 `chart_facts`** —— 它不是可复算的事实。它作为报告的 payload
走 `ai_reports` 的既有管线，与排盘报告同构。

---

## 7. 合规要点

1. 人脸信息属**敏感个人信息**，需单独同意：`user_consents` 记 `doc_type="face_biometric"`；
2. 图片有独立留存期，到期删除（`purge_expired_media`，可由定时任务调用）；
3. 输出必须带「AI 生成内容」标识（`warnings` + 前端提示）；
4. **明确不做**：健康诊断、身份识别、年龄推断、颜值评分；
5. 页面必须展示免责声明（`GET /vision/types` 返回，前端不硬编码）。

---

## 8. 接口

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| GET | `/vision/types` | 公开 | 分析类型、手别、免责声明、大小上限 |
| POST | `/vision/face/analyze` | 需登录 | multipart，必带 `Idempotency-Key` |
| POST | `/vision/palm/analyze` | 需登录 | 同上，另需 `hand_type` |
| GET | `/vision/media/{id}` | 需登录 | 取回自己的图片，不提供公开链接 |

限流：每类每小时 10 次（`VISION_HOURLY_LIMIT`），比文本报告更紧。
