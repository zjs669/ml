# 测试基准说明

本文说明"凭什么认为排盘是对的"。核心思路：**基准命例人工锁定 + 第二来源逐日交叉核验 + 口径差异单独立例**，三者缺一不可。

---

## 1. 基准命例 `tests/fixtures/bazi_cases.json`

结构（每条用例）：

```json
{
  "id": "case-014",
  "input": {
    "birth_datetime": "2024-02-04T16:20:00",
    "timezone": "Asia/Shanghai",
    "gender": "male",
    "time_known": true,
    "longitude": null,
    "convention": {}
  },
  "expected": {"year": "甲辰", "month": "丙寅", "day": "戊戌", "hour": "庚申"},
  "note": "立春交节 16:26，早于交节 → 年柱仍为癸卯（此例故意放在交节前）"
}
```

每条用例都必须记录：输入、期望四柱、口径、来源与说明。**没有来源的期望值不接受**。

覆盖维度（当前 24 例）：

| 维度 | 说明 |
| --- | --- |
| 普通日期 | 平日出生，四柱无边界问题 |
| 立春前后各 1 天 | 验证年柱切换 |
| 节气交接 ±5 分钟 | 验证交节时刻精度 |
| 23:00 / 00:30 | 验证换日口径 |
| 闰年 2/29 | 验证儒略日换算 |
| 世纪边界 | 1900 年前后与 2000 年前后 |
| 时区 `UTC` / `America/New_York` | 验证时区换算不双算 |
| 真太阳时开 / 关 | 验证经度修正 |
| 时辰不详 | 验证 `hour_known=false` 的降级表述 |

## 2. 第二来源交叉核验 `scripts/crosscheck.py`

- 用 `lunar-python`（MIT，**仅 dev 依赖**）作为第二来源，逐日扫描 1900–2100 年的四柱。
- 输出差异报告；容差只允许"节气 ±2 分钟导致的临界差异"，其余一律视为缺陷。
- 最近一次全量扫描：**2000 例抽样交叉核验通过，0 处不可解释差异**。

复跑方式：

```bash
cd backend
python -m scripts.crosscheck --samples 2000
```

## 5. 关键"锁死"断言

这几个断言一旦失败，说明地基动了，必须先查清再改：

1. **日柱锚点**：1949-10-01 为甲子日，JDN 2433191，`DAY_PILLAR_OFFSET=49`。`test_jiazi_bijection` 校验 60 甲子双射且无重复。
2. **换日口径差异**：23:30 的样例在 `zi_hour_policy_a` 与 `zi_hour_policy_b` 下日柱必须不同（丁巳 / 丙辰），时柱必须相同。
3. **年柱边界差异**：立春当天交节前的样例，`lichun` 与 `lichun_day` 必须给出不同年柱（癸卯 / 甲辰）。
4. **真太阳时**：87.6° 经度必须把时支从辰推到卯。
5. **关系规则无吉凶**：全部规则文本中不得出现吉、凶、大吉、灾、祸、必定、注定等词（`test_relations.py` 全表扫描）。
6. **并发唯一扣费**：10 线程同 `Idempotency-Key` 只能产生 1 条 `reserve`。
7. **反查与正排互逆**：固定 seed 随机 500 个 1800–2200 内的时刻，`calculate()` 得四柱后用 `reverse_search()` 反查，候选中必须包含该日期且时窗覆盖该时刻，要求 500/500。
8. **紫微宫干不越圈**：子宫、丑宫在寅之前，位移必须先落回十二宫一圈再压缩到十干；`test_ziwei_engine.py` 用两个 21 世纪子宫命例（2018-02-16、1999-12-31 23:30）锁死，改错会直接导致五行局偏移。
9. **紫微定位口诀**：水二局初一丑、木三局初一辰、金四局初一亥、土五局初一午、火六局初一酉五组起例全部对上，否则补数奇偶的进退方向反了。
10. **天府对称**：天府与紫微必须关于寅申轴对称，即 `天府宫 = (4 - 紫微宫) % 12`，`test_invariants` 每个基准命例逐盘校验。
11. **六爻八宫可推导**：`PALACE_SEQUENCE` 必须能由「本宫逐爻累变 → 游魂回变四爻 → 归魂复原内卦」独立重建，64 卦两表集合必须相等；`test_palace_sequence_matches_flip_rule` 逐宫重建后比对，世应再由「世上/一至五世即其数/游魂四/归魂三」推出。
12. **六爻变爻六亲以本卦宫为参照**：`liuyao-qian-two-moving`（乾为天初上动 → 泽风大过）是判别用例，丁未土按本卦乾金得父母、若误用变卦震木则会得妻财，四类用例一旦改错会直接挂在这里。
13. **奇门三盘是刚性旋转**：天盘九星、人盘八门、八宫神煞都必须表现为「本位序列在八宫环上的整体旋转」，任何一宫单独错位都说明旋转方向或基准宫算错了；`test_sky_stars_are_a_rigid_rotation_of_ring` 与 `test_doors_are_a_rigid_rotation_by_xun_step` 逐盘比对，八门还要求八个宫恰好各得一扇门（不重不漏）。
14. **奇门中五寄坤二**：中五宫必须无门、无神、无天盘干，且盘上恰好有一宫同时出现「天芮 + 天禽」并带中五地盘干；旬首落中五时值符取天禽、值使取坤二死门（`test_center_palace_has_no_door_or_deity`、`test_tianqin_rides_with_tianrui`）。
15. **JWT 六类攻击全部 401**：`alg=none`、签名篡改、`iss/aud` 不符、过期、access 当 refresh、登出后旧 access；另加 refresh 重放要连坐同族（`test_jwt_security.py`）。
16. **重置链接不泄露账号是否存在**：存在与不存在的邮箱，`forgot` 的 message 与 status 逐字相同，只有开发环境多一个 `debug_reset_url`。
17. **整形层不得凭空补内容**：空对象必须仍判不合格；模型自造的 `chunk_id`/`rule_id` 只能删不能补，且删掉的条数要写进 `uncertainties`（`test_report_coerce.py`）。
18. **追问不能引入新事实**：引用必须 ⊆ 原报告 `chunk_ids`，盘面断言走同一套 `DOMAIN_FACT_CHECKS`；不合格两次后返回 `degraded` 且只复述原报告已核验事实（`test_followup.py`）。
19. **密钥不得以明文落盘**：`encrypt_value` 结果不得包含原串，主密钥变更必须报错而不是返回空串，生产自检对明文直接失败（`test_secrets.py`）。
20. **蒸馏卡不参与事实校验**：卡片只能进 prompt 的「参考经验」段，`citations` 仍只认 `chunk_id`；`_draft/` 目录不递归加载（`test_skillfile.py`）。
21. **流年不改变四柱**：不传 `liunian_start_year` 时 `chart_facts` 不得出现 `liunian`；传了也只用 `(year-4)%60` 推干支，年界必须跟随 `year_boundary`（`test_bazi_liunian.py`）。
22. **复盘统计不得漏计未作答**：`got` 为空必须计入 `unanswered`，且蒸馏按题号累计错误次数而不是按记录条数（`test_bench_stats.py`）。
23. **题库必须先把盘算好再答题**：`birth_info` 转 `chart_input` 后，引擎失败要返回 `chart_error` 而不是抛异常；题干年份要映射成流年窗口（`test_bench_mingli.py`）。
24. **技能必读且不越界**：全局与领域 `SKILL.md` 无条件注入；`_draft/`、非 approved、跳 domain 一律不加载；总预算 ≤4000 字符（`test_skillfile.py`）。
25. **神煞不进关系链**：`chart_facts.shensha` 与 `triggered_rules` 分离，神煞没有 rule_id，也不影响关系计数（`test_bazi_shensha.py`）。

## 6. 紫微斗数基准 `tests/fixtures/ziwei_cases.json`

紫微没有可用的开源第二实现，所以基准只能靠**人工推行**。为避免「引擎自己和自己比」，每条用例都按以下顺序手动算一遍并写进 `derivation` 字段：

1. 农历年月日时（用 `lunar-python` 换算，作为独立于安星逻辑的事实源）；
2. 命宫、身宫（寅起正月顺数至生月，逆/顺数至生时）；
3. 命宫干支（五虎遁）与纳音五行局；
4. 紫微落宫（局数与生日）；
5. 十四主星按紫微系逆布、天府系顺布逐宫填写。

用例字段：

```json
{
  "case_id": "zw-1990-0520-wu-male",
  "input": {"birth_datetime": "1990-05-20T12:00:00", "timezone": "Asia/Shanghai", "gender": "male", "time_known": true},
  "lunar": "1990年四月廿六 午时",
  "expect": {
    "life_palace_branch": "亥",
    "body_palace_branch": "巳",
    "bureau": "土五局",
    "ziwei_branch": "亥",
    "main_stars": {"亥": ["紫微", "七杀"], "...": []}
  },
  "derivation": "……逐步行推文字……",
  "verified": "hand_derived"
}
```

当前 10 例，覆盖：子/午时命身同宫与不同宫、命宫空宫、常见主星组合（紫贪在酉、紫破在丑、武杀在酉、廉贪在巳、廉贞天府在戌）、21 世纪子宫宫干的负数取模陷阱、以及 23:30 的跨日边界。

**状态标注**：`verified` 目前均为 `hand_derived`（作者按古籍安星诀手推），**尚未经第三方研习者复核**。因此这 10 例的作用是「防止公式被改错」的回归锁，而不是「已获公认」的权威基准；补齐复核后应把 `verified` 改为 `reviewed` 并记录核验人。

断言分两层：

- `test_hand_derived_cases`：逐例比对命宫、身宫、五行局、紫微宫与十四主星分布，并反向检查「期望里没列出的宫位必须无主星」——防止多安星。
- `test_invariants`：十二宫齐全且与 `PALACES` 同序、十四主星各一、宫支不重复、身宫唯一、四化恰好四条且禄权科忌齐、大限起限岁等于局数且间隔 10 年、天府与紫微对称。

另有一组不依赖引擎的起例锚点：`ZIWEI_ANCHORS` 直接校验「水二局初一丑、木三局初一辰、金四局初一亥、土五局初一午、火六局初一酉」等 14 组，改错补数奇偶的进退方向会先挂在这里。

## 8. 奇门遁甲基准 `tests/fixtures/qimen_cases.json`

奇门的风险有三层：**局数（节气 + 符头 + 三元）**、**地盘布干**、**三盘在八宫环上的旋转**。三者任一写错，盘面看上去依旧完整，只是整体偏移一格，肉眼极难发现。因此期望值不取引擎输出，而按歌诀与环定义重建：

1. **局数**：先由 `prev_term()` 定二十四节气与阴阳遁，再由符头（甲日、己日）地支查四仲/四生/四墓定上中下元，最后查局数表；测试侧另用「上元 +6 得中元、再 +6 得下元（阴遁反向取 +3）」的歌诀递推关系校验整张表，并锚定六条原句（冬至一七四、立春八五二、芒种六三九、夏至九三六、立秋二五八、大雪四七一）。
2. **地盘**：自局数宫起，阳遁沿宫数递增、阴遁递减布「戊己庚辛壬癸丁丙乙」，要求九干是 1–9 宫的双射、局数宫必为戊、三奇乙丙丁恒在最后三位。
3. **值符 / 值使**：旬首所遁之仪落宫，取该宫本星为值符、本门为值使；中五宫无门，值使取寄宫坤二的死门。
4. **天盘**：值符加时干（甲时回到旬首宫），天盘干与天盘星同步旋转；测试侧把盘面按环序读出，与「本位序列整体旋转 offset 格」逐位比对。
5. **人盘**：值使门按旬内步数（`hour_index % 10`）阳顺阴逆移动，八门整体同步旋转。
6. **神盘**：自值符落宫起阳顺阴逆布八神；阴遁以勾陈、朱雀替换白虎、玄武。
7. **旬空 / 马星 / 伏吟**：旬空查六旬空亡表、马星查三合局表；星伏吟判据为值符未离旬首宫，门伏吟判据为旬内第 0 步。
