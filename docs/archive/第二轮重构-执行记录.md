## P0 导航与文案（先修「点了找不到」）

### 动机

16 个域里有 14 个只能从「工具」页二次跳转进入，顶部导航完全无入口。这是「新增功能上方没用」的直接原因。

### P0.1 建立唯一数据源 `src/config/domains.ts`

新增文件，把 19 个入口的元信息集中一处（现在分散在 `ToolsPage` 的 19 个对象、`HomePage` 的 5 个对象、`router` 的 19 条记录里，三份手工维护）：

```ts
export interface DomainEntry {
  domain: string        // 与后端 registry 一致；reverse/face/palm 用页面级 key
  path: string          // 路由
  label: string         // 中文名
  mark: string          // 单字徽标
  group: '命理' | '占卜' | '西式' | '视觉' | '工具'
  desc: string          // 一句话
  note: string          // 上线状态与边界
  requiresAuth?: boolean
}
export const DOMAIN_ENTRIES: DomainEntry[] = [ /* 19 条 */ ]
export const DOMAIN_GROUPS = ['命理', '占卜', '西式', '视觉', '工具'] as const
```

**验收**：新增一个域时只改这一个文件 + 后端 registry，`ToolsPage`/`HomePage`/`App.vue`/`router` 都不用动。

### P0.2 顶部导航改为「5 + 1 分组下拉」

- 一级保留：首页 / 工具 / 知识库 / 套餐

- 「工具」页保留为完整卡片视图（带说明与边界），下拉是快速跳转

**为什么不直接平铺 19 项**：19 个中文标签在 1280px 宽度下会换行或挤压，且「黄历/解梦」与「四柱/紫微」权重不同，平铺等于取消层级。

**验收**：`vue-tsc --noEmit` 通过；手动点一遍 19 个入口都能到对应页面。

### P2.2 前端 10 个薄壳页 → 1（见 P1.2）

### P2.3 `backend/app/domains/*/schemas.py` 15 个（**建议不动**）

57–99 行的 `schemas.py` 是各域的入参校验模型，与同目录 `engine.py` 强绑定。合并成 `schemas/all.py` 会让：

- `registry.py` 的「一个域一个包」边界失效
- `test_architecture.py` 的纯域隔离检查变复杂
- 改一个域的入参要动共享文件，冲突面变大

**结论：小是设计意图，不是缺陷。**

### P2.4 `frontend/src/api/types/` 14 个（**建议不动**）

同理，按域拆分是有意的（原本 837 行单文件，拆分后中位数 52 行）。合并会退回到「改一个域的类型要在 800 行里找」。

### P2.5 `scripts/` 其余 15 个（**建议不动**）

`smoke_e2e`(359) / `bench_eval`(456) / `eval_reports`(264) / `bench_stats`(250) 各自是独立入口，有独立 `--help` 和文档段落。合并会降低可发现性，且它们的依赖链不同（bench 系列依赖 `data/bench`，smoke 系列依赖运行中的服务）。

### 踩到的坑

1. **vite-node 双实例**：默认配置把 vue 预打包到 `node_modules/.vite/deps`，与源码 import 的 vue 冲突，SSR 的 `renderSlot` 抛 `Cannot read properties of null (reading 'ce')`。解法是新建 `vite.smoke.config.ts` 关掉 `optimizeDeps`。
2. **`useRoute()` 在 SSR 拿不到注入**：`DomainChartPage` 改用 props 传 `domain`，路由表里 `props: () => ({ domain })`。
3. **`routes` 不能从 `index.ts` import**：`index.ts` 末尾的 `createWebHistory()` 会摸 `window`，Node 里直接抛错。拆出 `routes.ts` 纯数据。
4. **`el-alert` 在 SSR 下不渲染内容**：`AstrologyBoard` 的「未实现项」警示块改用纯 div。
5. **进程生命周期**：`Start-Process` / `spawn` 起的服务在工具调用结束时被回收，必须用 `Win32_Process.Create`（CIM）才能留下。
