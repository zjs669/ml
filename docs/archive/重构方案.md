## 2. 许可证边界（硬约束）

`taibu/LICENSE` 原文划分：

| --- | --- | --- |
| `packages/core`、`packages/mcp`、`packages/mcp-server` | **MIT** | 可以，需保留 `LICENSE` 与 `THIRD_PARTY_NOTICES.md` |

**落地规则**：

1. 只读 `taibu/packages/core/src/domains/*/calculate.ts` 作为算法参考，在 Python 里重新实现；产出物不包含任何 TS 源码片段。

4. 不复制 `public/tarot_cards`（78 张图片，3.4 MB，AGPL + 来源不明），塔罗牌面自行生成或使用可商用素材。

`EngineSpec` 变更（`backend/app/domains/registry.py:41`）：

```python
@dataclass(frozen=True)
class EngineSpec:
    domain: str
    label: str
    input_model: type[BaseModel]
    calculate: Callable[[Any], ChartResult]
    schools: tuple[str, ...] = ("default_v1",)
```

## 4. 数据契约不变

所有新域必须返回既有 `ChartResult` 八字段外壳，字段语义按域约定：

| 字段 | 确定性域 | 生成式域 |
| --- | --- | --- |
| `chart_facts` | 引擎算出的结构事实 | 只放「用户输入摘要 + 媒体元信息」，**不放模型输出** |
| `triggered_rules` | 规则命中列表（带 `rule_id`） | 恒为空列表 |
| `warnings` | 流派差异、边界提示 | 「AI 生成内容」标识、图片质量提示 |
| `source_refs` | 古籍片段引用 | 题库条目 / 媒体哈希 |
| `algorithm_version` | 必填，形如 `almanac-engine-0.1.0` | 必填，形如 `face-prompt-0.1.0` |

这样 `backend/app/domains/reporting/`、`backend/app/api/v1/charts.py`、前端 `ChartBoard.vue` 分发器都**无需为新域改代码**。

## 6. 面相 / 手相（视觉能力）

### 6.1 现状缺口

`backend/app/domains/llm/openai_compatible.py` 的 `_payload()`（`openai_compatible.py:124`）只构造纯文本消息：

```python
"messages": [
    {"role": "system", "content": request.system_prompt},
    {"role": "user", "content": request.user_prompt},
]
```

**完全不支持图像**。这是本方案里唯一需要改动 LLM 基础设施的地方。

### 6.2 改造项

| 层 | 改动 |
| --- | --- |
| `llm/base.py` | `LLMRequest` 增加 `images: list[ImagePart] \| None = None`（保留 `user_prompt` 向后兼容） |
| `llm/openai_compatible.py` | `images` 非空时把 `content` 拼成 `[{"type":"text",...},{"type":"image_url","image_url":{"url":"data:<mime>;base64,..."}}]` |
| `core/config.py` | 新增 `llm_vision_model`、`llm_vision_base_url`、`llm_vision_api_key`；同步 `.env.example` |
| `models/chart.py` | 新增 `ChartMedia` 表（见 §8） |
| `api/v1/charts.py` | 新增 `POST /charts/face/analyze`、`POST /charts/palm/analyze` |
| `domains/vision/` | 提示词、分析类型枚举、JSON schema、免责声明**全部自写** |
| `services/` | 新增图片存储：落 `backend/var/media/`，库里只存 sha256 + 相对路径 |

### 6.3 分析类型（自拟，仅借鉴「按部位拆分」思路）

`full` 综合 / `forehead` 天庭 / `eyes` 眼相 / `nose` 鼻相 / `mouth` 口相 / `career` 事业 / `love` 感情；手相另加 `hand_type`（left/right）。

### 6.4 合规红线（必须写进文档与前端）

1. 人脸信息属**敏感个人信息**，需单独同意（复用现有 `user_consents` 表，`doc_type="face_biometric"`）
2. 图片留存期限可配置，到期由清理脚本删除（复用 `report_data_retention_days` 模式）
3. 上传即校验 MIME 白名单（jpeg/png/webp）+ 大小上限 + 服务端重新编码剥 EXIF
4. 输出必须带「AI 生成内容」标识（`warnings` + 前端徽章）
5. 明确不做：健康诊断、身份识别、年龄推断、颜值评分

### 13.4 执行中发现的真实 bug（计划里没预料到）

| bug | 暴露方式 | 修复 |
| --- | --- | --- |

「按定义独立重算」的测试，而不是拿引擎输出回填期望值。
