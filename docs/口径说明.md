# 口径说明

排盘不是"唯一真理"，而是**在明确口径下的一组确定结果**。本项目的原则是：

1. 口径不允许隐式默认——用户选了什么都写进 `convention` 并随命盘存档；
2. 结果里回显口径与算法版本，报告与导出文本同样标注；
3. 口径差异不当作 bug 修掉，而是写进 `warnings` 与「不确定项」，由用户切换比对。

---

## 1. 年柱边界 `year_boundary`

| 取值 | 含义 | 影响范围 |
| --- | --- | --- |
| `lichun`（默认） | 以**立春交节的具体时刻**切换年柱 | 出生时刻在立春当日、且早于交节时刻时，年柱仍属上一年 |
| `lichun_day` | 以立春当日 **00:00** 切换 | 忽略交节时刻，整日归入新年 |

两种口径只在「立春当天、交节时刻之前」这一小段内产生差异。系统会在 `warnings` 中提示距交节还有多少分钟。

## 2. 换日规则 `day_boundary`

| 取值 | 含义 | 日柱 | 时柱 |
| --- | --- | --- | --- |
| `zi_hour_policy_a`（默认） | 23:00 起算次日 | 23:00 后按**次日**干支 | 按次日子时起五鼠遁 |
| `zi_hour_policy_b` | 00:00 换日，23:00–23:59 为「夜子时」 | 23:00 后仍为**当日**干支 | 时干按次日子时推算 |

差异只出现在 23:00–23:59 之间。基准用例 `test_bazi.py::test_day_boundary_policies_differ` 固定了一组 23:30 的样例，保证两种口径的日柱确实不同、而时柱一致。

## 3. 时间修正 `solar_time`

| 取值 | 含义 |
| --- | --- |
| `none`（默认） | 直接使用输入的当地标准时间 |
| `true_solar_time` | 按经度差（每偏离标准时区中央经线 1° 修正 4 分钟）+ 均时差 EoT 修正 |

修正量在结果里以 `chart_facts.solar_time_adjust` 输出：

```json
{"applied": true, "delta_minutes": -14.4, "longitude": 87.6, "method": "longitude+eot"}
```

首版**不提供城市经纬度表**，只接受直接填写经度，避免维护一份无法追溯来源的城市数据。东经为正、西经为负。

## 4. 五行权重 `five_element_weight`

固定为 `weight-v1`，不允许选择：

| 位置 | 权重 |
| --- | --- |
| 天干 | 1.0 |
| 地支本气 | 1.0 |
| 地支中气 | 0.5 |
| 地支余气 | 0.3 |

结果同时给出 `raw`（纯计数）与 `weighted`（加权和），并列出 `missing`（原值为 0 的五行）。**`missing` 只陈述事实，不表示好坏**，前端也按这个措辞展示。

## 5. 流派 `school`

首版只有一个取值 `default_v1`。它的含义是：

- 年柱按立春、月柱用五虎遁、时柱用五鼠遁；
- 十神按「日干为主体 + 五行生克 + 阴阳同异」推导；
- 关系规则使用 `domains/relations/rules/*.yaml` 中登记的 48 条规则（版本 `relations-rules-0.1.0`）。

新增流派时应新增 `school` 取值与对应的规则版本，**不允许悄悄改旧版本的行为**。

## 6. 大运

- 顺逆：阳年男、阴年女顺排；阴年男、阳年女逆排。性别填「不填」时不计算大运，`dayun.computed=false` 并给出原因。
- 起运：按「出生时刻到相邻节气的天数 ÷ 3 = 年；余 1 日 = 4 个月；余 1 时辰 = 10 天」折算。
- 输出包含 `start_offset_days`、`start_age`、`start_datetime_estimate` 与 `error_bound`（误差边界文本），**误差边界会原样展示给用户**。

## 7. 节气时刻来源

`SolarTermService` 有两种实现，结果里的 `jieqi.prev.source` 会如实回显：

| source | 触发条件 | 说明 |
| --- | --- | --- |
| `lunar_python` | 环境里安装了 `lunar-python`（dev 依赖） | 作为运行时主源 |
| `builtin_meeus` | 未安装时自动回退 | 自研实现：Meeus《Astronomical Algorithms》太阳视黄经 + NASA ΔT 多项式 |

两者的交节时刻差异经单测约束在 **±900 秒**以内（`test_calendar.py::test_term_service_source_consistent`）。容器镜像只安装运行时依赖，因此容器内固定走 `builtin_meeus`；本机开发若装了 `lunar-python` 则走前者。**无论走哪条，报告都会回显 source，不存在"不知道用了什么"的情况。**

## 8. 关系规则

- 规则以 YAML 声明，字段：`rule_id / system / when / relation / priority / exceptions / source_ref / version / enabled`。
- `rule_id` 命名示例：`rel.branch.liuhe.zi_chou.v1`、`rel.stem.wuhe.jia_ji.v1`。
- 输出**只陈述触发了哪些规则、由哪些柱位触发**，不生成任何吉凶结论。
- 三合 / 三会 / 三刑缺一不构成完整关系，只进 `incomplete`，不算触发。
- 同一柱位同时出现「合」与「克」时进 `conflicts`，并列提示，不做优先级裁决。
- **天干相克**：只取同阴阳的 10 组（甲克戊、乙克己、丙克庚、丁克辛、戊克壬、己克癸、庚克甲、辛克乙、壬克丙、癸克丁），
  方向固定；阴阳相克不计入，避免与五合、相冲重复。
- **半会**：三会中相邻两支同时出现（寅卯、卯辰、巳午、午未、申酉、酉戌、亥子、子丑），
  只是「三会缺一」的结构标记，**不升格为三会**，优先级低于六合/三合。

当前规则总数：**66 条**（合类 23 + 冲刑害破 25 + 天干 19 − 重复口径按 YAML 实算），以 `load_rules()` 为准，不在测试里写死数字。

## 9. 四柱常见「看起来像 bug」的差异

| 现象 | 原因 |
| --- | --- |
| 23:30 出生换了日柱 | 换日口径不同，切 `zi_hour_policy_b` 比对 |
| 立春当天出生年柱不同 | 年柱边界口径不同 |
| 经度修正后时柱变了 | 真太阳时把时间推过了时辰边界 |
| 与某网站结果不同 | 对方的口径未标注；本站口径全部回显，可逐项对齐 |
| 交节前后 2 分钟内结果不同 | 节气瞬时值临界，`warnings` 会提示 |
| 「地势/自坐」与某些 App 不同 | 本版本十二长生按**土寄水（申）**、阳顺阴逆；另有一派土同火（寅），结果会差一两位 |
| 神煞数量比部分 App 少 | 勾绞、童子起法分歧大，默认不启用（`shensha_variant=extended` 才计算，并写入 warnings） |

遇到差异时，先对比 `convention`，再对比 `algorithm_version` 与 `jieqi.prev.source`；三项都一致而结果仍不同，才算缺陷。

## 10. 紫微斗数口径 `sanhe_default_v1`

紫微斗数的流派分歧远大于四柱，因此本版本**只实现一派**，并在 `convention` 里逐项回显；其他流派不提供开关，也不静默套用。「换一派看看」的诉求写在这里，不写进代码分支。

| 口径项 | 取值 | 说明 |
| --- | --- | --- |
| `calendar_basis` | `lunar` | 以农历月、日、时安星；公历输入由服务端先换算 |
| `year_boundary` | `lunar_new_year` | 生年干支按农历正月初一切换，不按立春 |
| `leap_month` | `as_current_month` | 闰月按**本月**安星，不并入下月 |
| `zi_hour` | `same_day` | 23:00–24:00 按**当日**之子时，不跳次日 |
| `school` | `sanhe_default_v1` | 三合派，安星按《紫微斗数全书》通行法 |

安星步骤（顺序固定，任一改动都会换盘，因此单独立例锁死）：

1. **命宫 / 身宫**：寅宫起正月顺数至生月，再自该宫起子时逆数至生时安命宫；顺数至生时安身宫（子时、午时命身同宫）。
2. **宫干**：按生年干起五虎遁。子宫与丑宫在寅之前，位移必须先落回十二宫一圈再压缩到十干，否则会错开两位。
3. **五行局**：命宫干支纳音定局——水二局、木三局、金四局、土五局、火六局。
4. **紫微星**：以局数与生日定宫，余数不足局数时按补数奇偶决定进退。
5. **十四主星**：紫微系（紫微、天机、太阳、武曲、天同、廉贞）逆布，天府系（天府、太阴、贪狼、巨门、天相、天梁、七杀、破军）顺布；天府与紫微关于寅申轴对称。
6. **辅星**：左辅右弼按生月，文昌文曲与地空地劫按生时，天魁天钺与禄存擎羊陀罗按生年干，火星铃星与天马按生年支三合。
7. **杂曜**（16 颗）：天刑天姚按生月（酉宫起正月，天刑顺、天姚逆）；红鸾（卯宫起子年逆）、龙池（辰顺）、凤阁（戌逆）、天哭（午逆）、天虚（午顺）、蜚廉（申顺）、天德（酉顺）、月德（巳顺）均按年支顺逆；华盖、咸池按年支三合；孤辰、寡宿按年支三会；破碎按四正/四生/四墓。流派歧义大的（解神、天巫等）本版本不收录。
8. **长生十二神**：水二局、土五局起申，木三局起亥，金四局起巳，火六局起寅；方向同大限（阳男阴女顺）。
9. **博士十二神**：禄存宫起博士，方向同大限。
10. **四化四层**：
    - 生年四化：按生年干，全盘固定；**庚干四化各派不一**（中州派作「太阳、武曲、天府、天同」），本版本采通行说「太阳、武曲、太阴、天同」，不做成开关。
    - 宫干四化：每宫天干各推一组，共 48 条，字段 `palace_transformations`（`from_palace / stem / type / star / to_palace`）。
    - 大限四化：仅在入参给出 `review_age` 时计算，取该年龄所在大限宫的宫干。
    - 流年四化：仅在入参给出 `review_year` 时计算，年份按**农历年**理解，年干支由 `(year - 4) % 60` 得出；同时给出流年命宫（流年支所在宫）。
11. **大限**：起限岁数等于五行局数，阳男阴女顺行、阴男阳女逆行；顺行即地支 +1（第二限落父母宫）。性别未填时按「阳年顺行」占位并在 `warnings` 声明。
12. **将前 / 岁前十二神**：将星由年支三合定（申子辰在子、寅午戌在午、巳酉丑在酉、亥卯未在卯）顺行；岁建由年支起顺行。
13. **小限**：男命命宫起 1 岁顺行、女命逆行，每宫隔 12 年（展示 1–120 岁）。
    **流年**：流年支所在宫为流年命宫，虚岁 = 公历年差 + 1；两者是独立的两条线，不互相替代。
14. **自化**：本宫宫干四化的目标星仍落在本宫时，记一条自化（禄/权/科/忌）。
15. **三方四正**：按十二宫顺序 `i / i+4 / i+8 / i+6` 取本宫、财帛、官禄、迁移，只用于定位，不参与吉凶。
16. **飞星串联**：从命宫、身宫（给了虚岁/年份时再加大限宫、流年宫）出发，按宫干四化逐层落宫，
    默认两跳（`flying_depth` 可选 1/2/3），每跳只取该宫第一条四化以避免组合爆炸；
    遇到重复宫位视为环路并标 `cycle`。

**本版本明确不做**：流年/流月的**吉凶推演**与格局高低；借对宫做吉凶判断（三方四正只画线定位）；
把飞星链路读成事件或应期（链路只回答「A 宫干化 X 入 B，再化 Y 入 C」）。

## 11. 紫微常见「看起来像 bug」的差异

| 现象 | 原因 |
| --- | --- |
| 命宫与别的软件差一宫 | 闰月取法（按本月 / 并入下月）或 23:00 是否换日不同 |
| 庚年生人的四化落宫不同 | 中州派作「太阳、武曲、天府、天同」，本版本采通行说 |
| 大限方向相反 | 性别未填（按阳年顺行占位），或对该年阴阳男女的判定口径不同 |
| 个别辅星位置不同 | 火星、铃星起宫有三合版本差异，本版本按「寅午戌人丑卯方」等四句起例 |
| 命宫为空宫 | 十四主星不落在命宫，属正常结构，本版本不借对宫、不代填星曜 |
| 同一颗星出现多条四化 | 生年、宫干、大限、流年各自独立成组；同一颗星可能既被生年化禄、又被某宫干化忌，这是四层并列，不是重复 |
| 没填年龄/年份就没有大限或流年四化 | 这是设计约束：没有入参就不推断年龄与流年，宁可缺一层也不猜 |
| 杂曜位置与手机 App 差一宫 | 红鸾、天哭一类杂曜在部分流派改用「月」起例，本版本统一用年支；差异已写在本节 |
| 星曜总数比部分软件少 | 本版本只收 16 颗规则无争议的杂曜，解神、天巫等有流派分歧的一律不收 |
| 小限年龄与某些 App 不同 | 小限起法与性别方向各派不同；本版本固定「男命宫起 1 岁顺行、女逆行」 |
| 流年表里的虚岁比周岁大 1–2 | 虚岁按公历年差 +1，不按农历生日重算 |
| 飞星链路只有两跳 | 默认 `flying_depth=2`；三跳条目会成倍增长，可在排盘页选 3 |
| 自化标记与生年四化重复 | 自化是「宫干四化仍落本宫」的独立标记，与生年四化不同层 |

遇到差异时，先比 `convention` 的五项取值与 `algorithm_version`，再看 `warnings` 是否已声明该情形；三项都一致而结果仍不同，才算缺陷。追问（`/reports/{id}/followups`）不改变上述口径：它只能引用原报告已引用的片段，不会因为追问而换一套安星法。

## 12. 六爻口径 `jingfang_najia_v1`

六爻的分歧集中在「怎么起卦」与「六亲以谁为参照」，因此本版本把这两件事写死在口径里，并在 `convention` 回显；起卦方式可在页面上选，但每种方式的规则只有一套。

| 口径项 | 取值 | 说明 |
| --- | --- | --- |
| `school` | `jingfang_najia_v1` | 京房纳甲：八宫卦序、纳甲、六亲、世应、六神一体 |
| `day_boundary` | `zi_hour_policy_a`（默认）/ `zi_hour_policy_b` | 与四柱共用同一换日口径，默认 23:00 换日 |
| `month_basis` | `solar_term` | 月建以「节」为界（大雪→子月、小寒→丑月…），不用农历月 |
| 六亲参照 | 本卦卦宫五行 | 变爻六亲同样对照本卦卦宫，不换成变卦卦宫 |
| 起卦法 | `coins` / `time` / `manual` | 三者并存，但同一张盘只用其中一种 |

装卦步骤（顺序固定）：

1. **日辰与月建**：日柱按所选换日口径取，月建取上一「节」对应的月支；旬空由日柱所在旬推出（甲子旬空戌亥、甲戌旬空申酉……）。
2. **起卦**：`coins` 由 `random.Random(seed)` 掷三枚钱六次（每爻 6–9）；`time` 按梅花易数取数——年支数 + 农历月 + 农历日为上卦、再加时支数为下卦，同一串数取 6 的余数为动爻，因此**只能有一个动爻**；`manual` 直接采信手填的 6/7/8/9。
3. **本卦与动爻**：6（老阴）与 9（老阳）为动爻；动爻阴阳反转即变卦。
4. **互卦**：取二三四爻为下卦、三四五爻为上卦，只用于结构参照，不参与六亲推算。
5. **卦宫与世应**：以八宫卦序（本宫、一世…五世、游魂、归魂）定宫位；世爻按「本宫在上爻、一世至五世即其世数、游魂在四、归魂在三」，应爻与世相隔三位。
6. **纳甲**：内卦三爻取下卦纳甲、外卦三爻取上卦纳甲（乾纳甲壬、坤纳乙癸、震庚、巽辛、坎戊、离己、艮丙、兑丁；阳卦地支顺行、阴卦逆行）。
7. **六亲**：以本卦卦宫五行为「我」，同我兄弟、生我父母、我生子孙、克我官鬼、我克妻财。
8. **六神**：甲乙日青龙起、丙丁日朱雀起、戊日勾陈起、己日螣蛇起、庚辛日白虎起、壬癸日玄武起，自初爻顺排至上爻。

**本版本明确不做**：取用神、旺衰生克、飞神伏神、应期推算、吉凶断语。盘面只输出本卦、动爻、变卦、互卦、纳甲、六亲、六神、世应与旬空这些**可逐项核对的事实**。

占问原文的处理：默认随盘保存；勾选「只存盘面」时服务端直接丢弃原文（不写库、不写日志），`chart_facts.question` 为 `null` 并附一条 warning。

## 13. 六爻常见「看起来像 bug」的差异

| 现象 | 原因 |
| --- | --- |
| 同一纳甲在两张盘里六亲不同 | 六亲是「爻支五行 vs 卦宫五行」的相对关系，换卦宫即换六亲，属正常 |
| 变卦六亲与本卦的算法不一致 | 本版本变爻六亲按**本卦卦宫**推算，改用变卦宫会得到另一套结果 |
| 23:30 起卦日辰比日历晚一天 | 默认 `zi_hour_policy_a`（23:00 换日），切到 `zi_hour_policy_b` 即按 00:00 |
| 月建与农历月不一致 | 月建以节气为界，农历月不能当月份用 |
| 时间起卦永远只有一爻动 | 梅花易数取数法本身只产生一个动爻；要多爻动请用铜钱或手填 |
| 铜钱起卦每次结果一样 | 同种子必然同结果（可复现），正式占问请掷实体铜钱后手填 |

遇到差异时，先比 `convention` 的 `school`、`day_boundary`、`month_basis` 与 `algorithm_version`，再看 `warnings`；四项都一致而结果仍不同，才算缺陷。

## 14. 奇门遁甲口径 `chaibu_zhuanpan_v1`

奇门是三术数里分歧最大的一门（置闰 / 拆补、转盘 / 飞盘、中宫寄宫、阴遁神名），因此本版本**只实现一套**：时家转盘拆补法。其他流派不是「暂不支持」，而是显式拒绝——`convention.school` 只取一个值，其余取值直接 422。

| 口径项 | 取值 | 说明 |
| --- | --- | --- |
| `school` | `chaibu_zhuanpan_v1` | 时家转盘 + 拆补定元，单一口径 |
| `dun_basis` | `solar_term` | 阴阳遁以二十四节气（含中气）为界：冬至→芒种阳遁，夏至→大雪阴遁 |
| `yuan_method` | `chaibu` | 上中下元按符头（甲日、己日）地支拆补，不用置闰法 |
| `center_palace` | `kun2` | 中五宫寄坤二宫，天禽随天芮同行 |
| `day_boundary` | `zi_hour_policy_a`（默认）/ `zi_hour_policy_b` | 与四柱共用换日口径；日柱变则符头与局数一起变 |

排局步骤（顺序固定，后一步依赖前一步）：

1. **四柱**：年柱以立春为界、月柱以「节」为界、日柱受换日口径影响、时柱五鼠遁；与四柱引擎同口径，避免同一时刻出现两套干支。
2. **阴阳遁**：取起局时刻之前的最近一个节气（含中气），冬至到芒种为阳遁，夏至到大雪为阴遁。
3. **符头与三元**：从当日（含）向前找最近的甲日或己日，地支子午卯酉为上元、寅申巳亥为中元、辰戌丑未为下元。
4. **局数**：查二十四节气三元局数表（冬至惊蛰一七四、小寒二八五……，口诀「阳遁顺推、阴遁逆推」）。
5. **地盘三奇六仪**：自局数宫起，阳遁按宫数递增、阴遁按宫数递减，布「戊己庚辛壬癸丁丙乙」。
6. **值符 / 值使**：旬首（甲子、甲戌…甲寅）遁于六仪之一，该仪所在宫的本星为值符、本门为值使；旬首落中五时，值符取天禽、值使取寄宫坤二的死门。
7. **天盘**：值符加时干（时干为甲时取旬首宫），天盘九星在八宫环上整体旋转，天盘干随之同步旋转，天禽随天芮。
8. **人盘**：值使门按旬内步数（时柱在旬内的序号 0–9）在八宫环上移动，阳遁顺行、阴遁逆行，八门整体同步旋转。
9. **神盘**：八神自值符落宫起阳遁顺布、阴遁逆布；阴遁以勾陈、朱雀替换白虎、玄武。
10. **旬空与马星**：旬空按时柱所在旬，马星按时支三合局（申子辰马在寅、寅午戌马在申、巳酉丑马在亥、亥卯未马在巳）。

**八宫环的定义**：坎一 → 艮八 → 震三 → 巽四 → 离九 → 坤二 → 兑七 → 乾六 为「顺行」，与八门本位序（休生伤杜景死惊开）一致，中五不入环。

**本版本明确不做**：取用神、旺衰生克、吉凶断语、择日择吉、应期推算、法术奇门、置闰法与飞盘奇门。盘面只输出局数、九宫星门神、旬空、马星、伏吟这些**可逐项核对的事实**。

之所以不接受手工指定局数：手工指定会让同一个问题的盘无法复核，也会让回归测试失去意义；局数必须能由「起局时刻 → 节气 → 符头 → 三元」完整重算出来。

## 15. 奇门常见「看起来像 bug」的差异

| 现象 | 原因 |
| --- | --- |
| 某一宫的星位旁多出一个「天禽」 | 天禽寄坤二随天芮同行，该宫的 `extra_star` 即天禽，地盘干同时带上中五的那个干 |
| 中五宫没有门、没有神、也没有天盘干 | 中五宫不布门神，天盘干随天芮落在坤二；属正常 |
| 时柱正好是旬首时整盘“不动” | 旬内第 0 步，天盘与地盘重合、值使门未离本位，即伏吟局 |
| 交节前后一两天局数突变 | 拆补法以符头定元；与置闰法在节气交界前后可能相差一局，本版本不提供置闰选项 |
| 23:30 起局的局数与 23:30 前不同 | 默认 `zi_hour_policy_a`（23:00 换日）使日柱进一位，符头跟着变 |
| 时干为甲时值符回到旬首宫 | 甲不单独遁宫，用旬首所遁之仪（戊己庚辛壬癸）的落宫 |
| 阴遁盘里找不到白虎、玄武 | 阴遁八神用勾陈、朱雀替代，属既定神名差异 |
| 值使门在八宫环上“跳过”中宫 | 中五不入环，八宫八门一一对应，一步就是一个宫 |

遇到差异时，先比 `convention` 的 `school`、`dun_basis`、`yuan_method`、`center_palace`、`day_boundary` 与 `algorithm_version`，再看 `warnings`；六项都一致而结果仍不同，才算缺陷。

## 16. 四柱流年窗口 `liunian`

流年**不是四柱的一部分**，而是给用户看的一个展示窗口。因此它不会默认出现：

| 项 | 规则 |
|---|---|
| 何时计算 | 仅当入参给了 `liunian_start_year` |
| 条数 | `liunian_years`，默认 10，上限 30 |
| 年干支 | `(year - 4) % 60`，1984 = 甲子、2024 = 甲辰、2026 = 丙午 |
| 年界 | **与年柱口径一致**：`lichun` 取立春交节时刻，`lichun_day` 取立春当日 0 点 |
| 虚岁 | `year - 出生公历年 + 1`（不按农历生日重算） |
| 十神 | 流年干对日主取十神，与四柱同一套口径 |
| 所属大运 | 按大运起运公历年归属，每步 10 年；未起运时为 `null` |

**为什么不默认从「今年」开始算**：默认值会让同一份输入在不同年份算出不同结果，违背「同一输入永远同一结果」。页面上的默认起始年只是表单初值，提交时会显式传入；保存命盘后该窗口也随盘冻结。

**流年不做的事**：不判流年吉凶、不做流年与大运的叠加、不取用神、不推月份。它只回答「这一年是什么干支、几岁、属于哪一步大运」。

大运本身仍是「性别未知则不推算」：起运顺逆依赖阳男阴女规则，没给性别就猜方向会直接错十年，因此界面上只提示「选性别后重新排盘」，不提供占位盘。

## 19. 黄历 `tongshu_daily_v1`

**换日**：按自然日 00:00 换日，**不采用**四柱的 23:00 换日。因此同一时刻在
「黄历」页与「四柱」页可能属于不同的日 —— 这不是 bug，是两个域的口径不同。

**条目来源**：宜、忌、值星、星宿、神煞、方位、九星全部取自 `lunar-python`（MIT，6tail）。
本仓库不自建条目表：黄历条目是**约定俗成的编纂结果**，不是可推导的天文事实，
自己编一份等于造一个没有出处的版本。

**个性化**：给出生日期只做「日主/生肖对照标注」，**不参与宜忌判定**。
不同通书版本条目可能不一致，页面只呈现当前数据源的条目。

**不做什么**：不做择日推荐、不做时辰择吉、不做个人命局配合。

## 20. 小六壬 `liugong_digui_v1`

**递推**：月上起大安 → 顺数至农历月 → 从月宫起顺数至农历日 → 从日宫起顺数至时辰。
三宫固定顺序：大安 → 留连 → 速喜 → 赤口 → 小吉 → 空亡。

**闰月**：默认 `repeat`（闰月按本月重数）；切 `advance` 则顺延为下一月。
两种口径在闰月当月会得到不同落宫。

**时辰**：`clock` 模式按 0–23 小时换算（23:00 起子时）；`shichen` 模式直接给 1–12。
两种模式语义不同，不要混填。

**不做什么**：不推应期、不给吉凶结论、不涉及掌诀起课。

## 21. 梅花易数 `shaoyong_tongxing_v1`

**起卦法**：时间 / 报数（两数、三数）/ 字占 / 丈尺 / 方位 / 直接指定，共六种。
上下卦数除 8 取余（余 0 作 8），动爻数除 6 取余（余 0 作上爻）。

**卦表复用**：六十四卦的卦名与卦宫取自 `liuyao.hexagrams`，不另立一份。
六爻域已有独立推导测试锁死这张表，复用比重抄安全。

**字占笔画是近似值**：按「字数 × 10」估算，**不查笔画表**。理由是汉字笔画表体积大、
各版本有差异，查表会引入无法验证的数据源。这条写进了 `warnings`。

**体用**：动爻所在卦为用，另一卦为体；只列五行与生克方向（同我/生我/我生/克我/我克），
不判断吉凶。

## 22. 大六壬 `zeike_zhugan_v1`

**范围**：本版本实现主干 —— 月将加时定天地盘、贵人顺布十二天将、四课、贼克法三传（含比用法）。

**未实现的课体**：涉害、遥克、昴星、别责、八专、伏吟、返吟。遇到这些情形时
`san_chuan` 为 `null`，`san_chuan_status.implemented=false` 并写明原因。
**不硬凑结果**：课体判定各版本优先级不同，给一个「看起来完整但可能错」的三传
比明确说「不判」危险得多。

**天将坐标系**：天将挂在**天盘支**上。盘面读法是「地盘某宫 → 天盘某支 → 临某将」。
把天将挂在地盘支上再按天盘支查询，会让每个宫位的将都错位 —— 而盘面上十二将齐全、
顺序也对，肉眼几乎发现不了。单测专门锁定了这一点。

**天盘位移方向**：`sky[时支] = 月将`，其余按 `sky[earth] = 月将 + (earth − 时支)`。
写反会得到一张整体偏移的天盘，同样「看起来完整」。

## 23. 太乙九星 `jiuxing_observation_v1`

**范围**：年/月/日/时四层九星观测（编号、太乙名、五行、方位、传统吉凶分类）。
**不做**：七十二局、主客算、大小将、十六神。这些需要《太乙金鏡式經》的整张局表，
且各版本表项不一致，不能用某一个程序作唯一真值。

**时层九星是独立实现**：`lunar-python 1.4.8` 的 `LunarTime.getNineStar()` 把
`Solar` 对象与字符串直接比较，运行期抛 `TypeError`。本仓库按同一套规则
（阳起 7 / 阴起 3，子午卯酉与辰戌丑未另有起数）自行实现，并用单测逐项锁定起数与方向。

## 24. 塔罗 `rider_waite_v1`

**抽牌**：无放回，同一牌阵内不会出现重复牌。牌序与正逆位使用**两个独立随机源**
（不同盐值的 SHA-256 派生），因此同一 `seed` 可完整复现，且抽 1 张时正逆位分布不退化。

**牌面数据**：牌名与编号是 Rider–Waite 体系的公有结构；关键词为自编简表。
**牌面图片不随仓库分发**。

**不做什么**：不做事件预测、不给吉凶结论、不把关键词串成断语。

## 25. 西洋占星 `simplified_sun_moon_v1`

**这是简化版，必须如实标注**：

| 项目 | 状态 | 精度 |
| --- | --- | --- |
| 太阳视黄经 | 已实现（Meeus 低精度式） | 约 ±0.01° |
| 月亮黄经 | 已实现（Meeus 第 47 章前 7 项主摄动） | 约 ±0.3° |
| 上升点 / 天顶 | 已实现（恒星时 + 黄赤交角 + 纬度） | 受出生时刻精度影响 |
| 宫位 | 整宫制（whole sign） | 定义精确，与 Placidus 结果不同 |
| 十行星 / 交点 / 莉莉丝 | **未实现** | — |

**为什么不做十行星**：`pyswisseph` 需要 MSVC 编译（实测报
"Microsoft Visual C++ 14.0 or greater is required"），本机装不上；自研摄动级数在
0.1° 量级不可靠。未实现项通过 `chart_facts.unavailable` **显式列出**，不静默省略。

**极圈内纬度直接拒绝**：`|latitude| > 66°` 时上升点可能不存在，接口返回 422 而不是
给一个错误值。

## 26. 紫微运限 `sanhe_default_v1`

**六层递推**：大限（虚岁落在大限表区间）→ 小限（虚岁查小限表）→ 流年（流年支对应宫）
→ 流月（斗君法：流年宫逆数生月，再起子时顺数生时）→ 流日（自流月宫起初一顺行）
→ 流时（自流日宫起子时顺行）。

**本命盘口径完全交给 `ziwei` 域**：运限不重算任何安星，只在本命盘结果上叠时间层。
`transit_transformations` 复用本命盘已算好的宫干四化，不重推四化表。

**虚岁**：目标农历年 − 出生农历年 + 1。虚岁超出 12 个大限覆盖范围时，大限层留空并提示。

## 27. 紫微飞星 `sanhe_default_v1`

**三类查询**：`flies_from`（某宫飞向哪些宫）、`flies_into`（哪些宫飞入某宫）、
`flies_to`（两宫之间是否有飞化）。

**与 `ziwei` 的 `flying` 的区别**：`ziwei` 的 `flying` 是「命宫起两跳的串联概览」，
本域是**定向查询**。两者输入形态不同（深度参数 vs 起点/终点），塞在一起会让
`ziwei` 的入参变成万能参数袋。

**空四化列表按全部处理**（`empty_means_all=true`），不是「无四化」。

**不做什么**：不做「禄转忌」「忌转忌」这类复合推演。

## 28. 关系合盘 `bazi_cross_v1`

**复用单盘规则**：跨盘关系与盘内关系用的是**同一套 66 条 YAML 规则**。
`relations.detect_relations` 增加了 `positions` 参数以支持跨盘位置名
（`L_year` … `R_hour`），规则判定循环没有第二份实现。

**分组**：位置前缀不同即「跨盘」，同前缀即「盘内」。双方干支完全相同时跨盘关系仍然成立
（不会因位置名相同而被覆盖）。

**三种输入来源**：已保存盘 `chart_id` / 出生时间 / 直接给四柱。直接给四柱时
会在 `warnings` 标注「未经验证」，因为它可能来自其他口径（年界、日界不同会改变干支）。

## 29. 性格问卷 `self_authored_four_dim_v1`

**题库是自编的**：40 题（每维 10 题），不复制任何第三方题库。
通行版本为 90+ 题，本版本规模更小，信度更低，**结果页必须标注「精简版，仅供参考」**。

**平票记 `X`**：40 题版本每维只有 10 题，5:5 是真实可能出现的状态。硬归到某一极
会制造「测出来很确定」的假象，比标未分化更糟。

**不是官方 MBTI**：实现的是「四维二分倾向问卷」这一公开的测量思路，
不声称是官方量表，不输出官方类型的诊断结论。

## 30. 解梦 `keyword_lookup_v1`

**只做两件事**：从梦境描述里抽取意象关键词，列出该意象的民间通行说法。

**为什么用固定词表而不是分词库**：解梦的匹配对象是**意象名词**，词表匹配召回率足够，
且结果可解释（用户能看出「为什么命中了这个词」）；分词库对「梦见」「看到」这类动词的
处理不一致，还会引入额外依赖。

**长词优先**：按词长倒序匹配，命中后占用位置，避免「水」把「小河」吃掉。

**未命中显式标记**：`unmatched=true` 并提示「本词表覆盖不足」，**不硬套近义词**。

## 31. 面相 / 手相 `*_vision_v1`

**本质不是引擎**：没有确定性算法，是「图片 + 提示词 → 视觉模型」。
因此它们**不进 `registry`**，走独立的 `/vision/*` 路由（需要登录、消耗额度、落盘图片）。

**三条硬约束写进提示词**：
1. 只描述图像上确实可见的形态，看不清的写进 `uncertainties`；
2. 不推断性格、智力、健康、寿命、命运、财富、婚姻、事业成败，不评价外貌；
3. 传统说法必须放 `traditional_interpretations` 并标注「属传统说法，无实证依据」。

**图片处理**：MIME 白名单（jpeg/png/webp）、单边 ≤ 4096、≤ 5 MiB、上传即重编码剥 EXIF
（含 GPS、设备型号、拍摄时间），按内容寻址去重，到期由清理脚本删除。

**未配置视觉模型时返回 503**，**不回落到文本模型** —— 文本模型看不懂图片，
会一本正经地编造「照片里的形态」，比直接报错危险得多。

**`chart_facts` 只放用户输入与媒体元信息**，模型输出走 `ai_reports`，不进事实层。
