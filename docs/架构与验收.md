# 架构与验收

> 这一页写给维护者：代码边界、守卫规则、例外与验收分层。
> 和 taibu 的 `docs/manual/Architecture.md` 同一用途——先说清“谁能依赖谁”，
> 再把“怎么算通过”拆成几层，避免用一句「测试通过」掩盖没验的部分。

---

## 1. 总体方向

模块化单体，不引微服务、事件总线、DI 容器或第二套认证：

- 四个术数共用同一个 `ChartResult` 外壳与同一条校验链；
- 计算与解释分离：引擎只产事实，模型只做解释，服务端校验引用；
- 所有口径写进 `convention` 并随盘存档，换口径必须显式。

不做的：把数据库访问藏进领域层、在 API 里写业务规则、为每个术数复制一套报告管线。

---

## 2. 职责边界

| 层 | 目录 | 负责 | 不负责 |
|---|---|---|---|
| HTTP 装配 | `app/api` | 路由、鉴权、额度、请求/响应映射 | 提示词、SQL、排盘算法 |
| 计算内核 | `app/domains/{bazi,ziwei,liuyao,qimen,calendar_core,relations}` | 纯函数排盘与规则匹配 | 数据库、网络、模型、计费 |
| 报告编排 | `app/domains/reporting` | 取数、拼 prompt、调用模型、校验、降级 | 直接写库（走 repositories） |
| 模型接入 | `app/domains/llm` | Provider 抽象、OpenAI 兼容、Mock、校验器 | 业务规则 |
| 技能 | `app/domains/skills` | 任务包加载、`SKILL.md` 注入 | 事实与引用 |
| 持久化 | `app/repositories` | SQL 与事务 | 业务判断 |
| 模型层 | `app/models` | ORM 表定义 | 查询逻辑 |
| 基础设施 | `app/core` | 配置、数据库、安全、日志、加密 | 任何领域逻辑 |
| CLI | `backend/scripts` | 评测、蒸馏、冒烟、加密 | 被 `app` 反向引用 |
| 浏览器契约 | `frontend/src/api` | 类型、axios 封装 | 依赖页面/组件/路由 |
| UI | `frontend/src/{components,pages}` | 展示与交互 | 直接拼后端契约 |

## 3. 守卫规则（`backend/tests/test_architecture.py`）

| 断言 | 为什么 |
|---|---|
| `core` 不 import api/domains/repositories/models | 基础设施必须最底层，否则任何循环都从这里开始 |
| `models` 不 import api/domains | 表定义不认识业务 |
| `repositories` 不 import api/domains | 仓储只做 SQL，不能反向依赖业务 |
| `api` 不 import `app.domains.llm` | 模型调用只能经 `reporting`，避免绕过校验与额度 |
| 纯计算域不 import 数据库/HTTP/LLM/计费 | 引擎必须能离线复算，否则基准测试会退化成集成测试 |
| `_*.py`、`tmp_*`、`shots/` 不得存在 | 临时脚本与截图不留在仓库 |
| `skills/distilled.py` 保持删除 | 已被 `skillfile` 取代，防止两套注入并存 |
| 技能只能从 `skillfile` 导入 | 报告/追问/评测共用一次实现 |
| `frontend/src/api` 不 import UI/路由/store | 契约层不能反向依赖展示层 |

规则只写「已经做到且必须保持」的边界。想放宽时，先改这张表和测试，再改代码，不允许只在代码里破例。

## 4. 技能与知识源

三者的区别见 [技能与知识源.md](技能与知识源.md)，这里只记边界结论：

- **任务包**（`skills/packages/*.json`）决定模板与检索主题，不含经验；
- **SKILL.md**（`backend/skills/**`）每次注入，但不是事实来源，也不得写进 `citations`；
- **知识库**（`knowledge_chunks`）才可引用，只返回 `approved`；
- **外部包**（taibu）只读挂载，默认仅评测使用，不复制、不执行其引擎。

## 5. 验收分层

| 层 | 命令 | 验证什么 | 不能替代 |
|---|---|---|---|
| 1 工程检查 | `pytest -q`；`npm run build` | 类型、单测、架构守卫、构建 | 真实模型与浏览器 |
| 2 引擎基准 | `pytest tests/test_bazi.py tests/test_ziwei*.py tests/test_relations.py` | 算法与规则可复算 | HTTP 契约 |
| 3 HTTP 契约 | `pytest tests/test_api_*.py`；`python -m scripts.smoke_api` | 状态码、鉴权、越权、幂等 | 真实前端交互 |
| 4 真实模型 | `python -m scripts.eval_reports --cases 10` | schema、引用合法率、降级率、延迟 | 模型“答得对不对” |
| 5 题库 | `python -m scripts.bench_eval ...`；`distill_round` | 准确率、知识命中、消融 delta | 产品红线 |
| 6 浏览器 | 手工或 headless 截图 | 排盘展示、表单、追问交互 | 生产数据 |

原则：下层通过不等于上层通过；真实模型跑通不等于题库准确率达标；截图好看不等于口径正确。

## 6. 已知例外与删除条件

| 例外 | 为什么保留 | 删除条件 |
|---|---|---|
| `scripts/smoke_api.py` 与 `smoke_e2e.py` 并存 | 前者用 TestClient 不需起服务，后者跑真实端口 | 两者职责合并且覆盖不降 |
| 任务包仍叫 `packages/*.json` | 外部脚本与文档已引用 | 统一改名时同步迁移并更新文档 |
| `app/api` 里出现 `sqlalchemy.orm.Session` | 仅作依赖注入类型标注 | 引入统一 `DbSession` 别名后可去掉 |
| 外部 taibu 技能包 | 只读挂载、评测用 | 不再需要其分析框架时移除配置 |
| `skills/_draft/` 人工闸门 | 模型不能给自己定规则 | 永不删除 |

---

## 7. 变更与回滚

- **删兼容层**：先有替代实现与对应测试，再加“保持删除”断言；不能因为“已经新建文件”就删。
- **改口径**：同步 `docs/口径说明.md`、基准用例与 `convention` 字段，并在结果页可回显。
- **改表结构**：必须带 Alembic migration；不写破坏性 down migration。
- **新增术数**：注册表 + 引擎 + 口径章节 + 基准用例 + 知识源目录 + `SKILL.md`，缺一不发版。
- **回滚**：按术数/领域回退，不同时改结果格式与数据库布局。
